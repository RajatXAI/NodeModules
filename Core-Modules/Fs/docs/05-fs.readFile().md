# Introduction

`fs.readFile()` is the asynchronous version of `fs.readFileSync()`.

Instead of blocking JavaScript until the file is read, it starts the file operation and continues executing the remaining code.

Once the file has been read, the callback function is executed.

This is the preferred way of reading files in backend applications.

---

# Why readFile()?

Imagine your server receives multiple requests.

```
Client 1

↓

Read File

↓

Response
```

At the same time

```
Client 2

↓

Read File

↓

Response
```

If the server waits for every file operation to complete, all other requests will also have to wait.

To avoid this problem, Node.js provides asynchronous file operations.

---

# Syntax

```js
fs.readFile(path[, options], callback);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| path | File path |
| options | Encoding or configuration |
| callback | Function executed after the file is read |

---

# Callback Function

The callback receives two arguments.

```js
(error, data)
```

Example

```js
fs.readFile("data.txt", "utf8", (error, data) => {

});
```

### error

Contains the error if the operation fails.

Otherwise

```
null
```

---

### data

Contains the file contents if the operation succeeds.

---

# Return Value

Unlike `readFileSync()`,

`readFile()` does **not** return the file contents.

Instead,

the data is available inside the callback function.

---

# Internal Working

Suppose

```js
fs.readFile("data.txt", "utf8", callback);
```

Execution Flow

```
Application

↓

FS Module

↓

libuv

↓

Operating System

↓

Read File

↓

Callback Queue

↓

Event Loop

↓

Execute Callback
```

Notice

JavaScript does not wait.

It continues executing other code.

# Reading a Text File

Project Structure

```
project/

├── app.js

└── data.txt
```

data.txt

```text
Hello Node.js
```

app.js

```js
const fs = require("fs");

fs.readFile(
    "data.txt",
    "utf8",
    (error, data) => {

        if (error) {
            console.log(error);
            return;
        }

        console.log(data);

    }
);

console.log("File Reading Started...");
```

Output

```text
File Reading Started...

Hello Node.js
```

Notice

The last `console.log()` executes before the callback.

# Reading a JSON File

config.json

```json
{
    "port": 3000,
    "database": "MongoDB"
}
```

Code

```js
const fs = require("fs");

fs.readFile(
    "config.json",
    "utf8",
    (error, data) => {

        if (error) {
            console.log(error);
            return;
        }

        const config = JSON.parse(data);

        console.log(config);

    }
);
```

# Error Handling

Always check for errors first.

```js
if (error) {

    console.error(error.message);

    return;

}
```

This pattern is called the **Error-First Callback Pattern**.

It is used throughout many Node.js APIs.

# Best Practices

✅ Always handle errors.

✅ Use encoding for text files.

✅ Prefer asynchronous APIs inside servers.

✅ Keep callback functions small and readable.

---

# Common Mistakes

### Forgetting Error Handling

```js
fs.readFile("data.txt", "utf8", (error, data) => {

    console.log(data);

});
```

Always check the error first.

---

### Expecting Immediate Return

Incorrect

```js
const data = fs.readFile(...);
```

`readFile()` does not return the file contents.

---

### Using readFileSync() in Request Handlers

Prefer `readFile()` for better scalability.

# Key Takeaways

- `fs.readFile()` reads files asynchronously.
- JavaScript continues executing while the file is being read.
- File data is available inside the callback function.
- Always handle errors before using the data.
- `readFile()` is the recommended choice for production backend applications.
