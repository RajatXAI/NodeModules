# Introduction

`fs.promises.rename()` is the Promise-based version of `fs.rename()`.

Instead of callbacks, it returns a Promise.

This allows us to use `async/await`, making the code cleaner, easier to read, and easier to maintain.

This API can

- Rename files
- Rename directories
- Move files
- Move directories

---

# Why fs.promises.rename()?

Imagine a user uploads a profile image.

Initially

```
uploads/

└── 84ca921.png
```

After processing

```
images/

└── profile.png
```

The file should be moved and renamed.

`fs.promises.rename()` performs both operations.

# Syntax

```js
await fs.rename(oldPath, newPath);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| oldPath | Current path |
| newPath | Destination path |

---

# Return Value

Returns a Promise.

If the operation succeeds,

the Promise is resolved.

If something goes wrong,

the Promise is rejected.

The method itself does not return any data.

```
Application

↓

↓

libuv

↓

↓
```

# Error Handling

Always use

```js
try...catch
```

```js
const fs = require("fs").promises;

async function main() {

    try {

        await fs.rename(

            "missing.txt",

            "new.txt"

        );

    } catch (error) {

        console.log(error.message);

    }

}

main();
```

# Common Mistakes

### Forgetting await

```js
fs.rename(

    "a.txt",

    "b.txt"

);

console.log("Done");
```

The rename operation may still be running.

---

### Assuming rename() Creates Missing Directories

```js
await fs.rename(

    "photo.jpg",

    "images/profile/photo.jpg"

);
```

If

```
images/profile/
```

does not exist,

Node.js throws an error.

Create the directory first using

```js
await fs.mkdir(
    "images/profile",
    {
        recursive: true
    }
);
```

---

### Ignoring Errors

Always use `try...catch`.

# Key Takeaways

- `fs.promises.rename()` can both rename and move files or directories.
- It returns a Promise and works with `async/await`.
- It does not create missing destination directories automatically.
- Always handle errors using `try...catch`.
- It is the recommended API for modern Node.js applications.
