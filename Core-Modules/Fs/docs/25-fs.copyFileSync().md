# Introduction

`fs.copyFileSync()` is the synchronous version of `fs.copyFile()`.

It copies a file from one location to another.

Unlike `renameSync()`,

the original file is **not removed**.

After copying,

both the original file and the copied file exist.

---

# Why copyFileSync()?

Suppose your application stores uploaded files.

Before compressing an image,

you want to keep a backup.

```
Original Image

↓

Create Backup

↓

Compress Copy
```

Instead of moving the original,

Node.js creates another copy.

---

# Syntax

```js
fs.copyFileSync(src, dest[, mode]);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| src | Source file path |
| dest | Destination file path |
| mode | Optional copy behavior |

---

# Return Value

`fs.copyFileSync()` returns

```js
undefined
```

If an error occurs,

Node.js throws an Error.

# Copy Modes

Node.js provides an optional mode.

Most commonly used

```js
fs.constants.COPYFILE_EXCL
```

Example

```js
const fs = require("fs");

fs.copyFileSync(

    "a.txt",

    "b.txt",

    fs.constants.COPYFILE_EXCL

);
```

If

```
b.txt
```

already exists,

Node.js throws an error instead of overwriting it.

---

# Error Handling

Always use

```js
try...catch
```

```js
const fs = require("fs");

try {

    fs.copyFileSync(

        "source.txt",

        "backup.txt"

    );

    console.log("Copied");

} catch (error) {

    console.log(error.message);

}
```

---

# Common Error Codes

| Error Code | Meaning |
|------------|---------|
| ENOENT | Source file does not exist |
| EACCES | Permission denied |
| EPERM | Operation not permitted |
| EEXIST | Destination already exists (with `COPYFILE_EXCL`) |

# Best Practices

✅ Always use `try...catch`.

✅ Verify that the source file exists.

✅ Use `COPYFILE_EXCL` when overwriting should not be allowed.

✅ Prefer Promise APIs in modern backend applications.

# Common Mistakes

### Thinking copyFileSync() Removes the Original File

Incorrect.

The original file remains unchanged.

---

### Destination Directory Does Not Exist

```js
fs.copyFileSync(

    "a.txt",

    "backup/files/a.txt"

);
```

If

```
backup/files/
```

does not exist,

Node.js throws an error.

Create the directory first using

```js
fs.mkdirSync(
    "backup/files",
    {
        recursive: true
    }
);
```

---

### Forgetting try...catch

Synchronous APIs throw errors directly.

# Key Takeaways

- `fs.copyFileSync()` creates a copy of a file while keeping the original unchanged.
- It blocks JavaScript until the copy operation is complete.
- Use `COPYFILE_EXCL` to prevent accidental overwriting.
- Handle errors using `try...catch`.
- It is useful for backups, templates, caching, and file processing.
