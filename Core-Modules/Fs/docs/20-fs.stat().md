# Introduction

`fs.stat()` is the asynchronous version of `fs.statSync()`.

Instead of blocking JavaScript, it retrieves file or directory metadata in the background.

When the metadata is ready, the callback function is executed.

It does **not** read the file contents.

It only returns information about the file or directory.

---

# Why stat()?

Suppose a user uploads a file.

Before processing it, your application wants to check

- Does the file exist?
- Is it actually a file?
- Is it smaller than 5 MB?

Instead of reading the entire file,

Node.js can quickly return its metadata using `fs.stat()`.

---

# Syntax

```js
fs.stat(path[, options], callback);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| path | File or directory path |
| options | Optional configuration |
| callback | Function executed after metadata is retrieved |

---

# Callback Function

The callback receives two arguments.

```js
(error, stats) => {

}
```

### error

Contains an Error object if the operation fails.

Otherwise

```js
null
```

---

### stats

A `Stats` object containing metadata about the file or directory.

---

# Return Value

`fs.stat()` returns

```js
undefined
```

The metadata is available inside the callback.

---

# Reading File Information

Project Structure

```
project/

├── app.js

└── notes.txt
```

Code

```js
const fs = require("fs");

fs.stat(

    "notes.txt",

    (error, stats) => {

        if (error) {

            console.log(error);

            return;

        }

        console.log(stats);

    }

);
```

# Checking File or Directory

```js
const fs = require("fs");

    "notes.txt",

    (error, stats) => {
```

# Error Handling

Always check the error first.

```js
const fs = require("fs");

fs.stat(

    "missing.txt",

    (error, stats) => {

        if (error) {

            console.log(error.message);

            return;

        }

        console.log(stats);

    }

);
```

Example Output

```
ENOENT: no such file or directory
```

# Most Useful Stats Properties

| Property | Real-world Usage |
|----------|------------------|
| size | Validate upload size |
| birthtime | Display creation date |
| mtime | Detect modified files |
| atime | Track last access time |
| isFile() | Process only files |
| isDirectory() | Process only directories |

# Practical Lab

Project Structure

```
fs-learning/

├── app.js

└── image.png
```

app.js

```js
const fs = require("fs");

fs.stat(

    "image.png",

    (error, stats) => {

        if (error) {

            console.log(error.message);

            return;

        }

        console.log("Size:", stats.size);

        console.log("Is File:", stats.isFile());

        console.log("Modified:", stats.mtime);

    }

);
```

Expected Output

```text
Size: 58231

Is File: true

Modified: 2026-08-08T...
```

# Best Practices

✅ Always check the error first.

✅ Use `isFile()` before reading a file.

✅ Validate upload size before processing.

✅ Prefer Promise APIs in modern Node.js applications.

---

# Common Mistakes

### Confusing stat() with readFile()

`stat()` returns metadata.

It does **not** return file contents.

---

### Ignoring Errors

Always handle missing files and permission issues.

---

### Assuming Every Path Is a File

Always verify using

```js
stats.isFile()
```

or

```js
stats.isDirectory()
```

# Key Takeaways

- `fs.stat()` retrieves metadata asynchronously.
- It returns a `Stats` object inside the callback.
- It does not read the file contents.
- Use `isFile()` and `isDirectory()` to determine the path type.
- Always check the error before using the `Stats` object.
