# Introduction

`fs.writeFile()` is the asynchronous version of `fs.writeFileSync()`.

Instead of blocking JavaScript while writing data to a file, it starts the write operation and immediately continues executing the remaining code.

When the file is successfully written (or an error occurs), the callback function is executed.

This API is commonly used in backend servers because it does not block the event loop.

---

# Why writeFile()?

Imagine an API that generates invoices.

```
Client

↓

Generate Invoice

↓

Write invoice.pdf

↓

Send Response
```

If the server waits until the file is written, other incoming requests also have to wait.

Using `writeFile()` allows the server to continue handling other requests while the file is being written.

---

# Syntax

```js
fs.writeFile(file, data[, options], callback);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| file | File path |
| data | Data to write |
| options | Encoding or configuration |
| callback | Function executed after writing completes |

---

# Callback Function

The callback follows the **Error-First Callback Pattern**.

```js
(error) => {

}
```

If the operation succeeds,

```js
error
```

will be

```js
null
```

If something fails,

it contains the error object.

---

# Return Value

`writeFile()` does **not** return the written data.

It immediately returns

```js
undefined
```

The result is available inside the callback function.

---

# How writeFile() Works

Suppose

```js
fs.writeFile(
    "notes.txt",
    "Hello",
    callback
);
```

Execution Flow

```
Application

↓

FS Module

↓

libuv

↓

Operating System

↓

Write File

↓

Callback Queue

↓

Event Loop

↓

Execute Callback
```

Notice

JavaScript continues executing while the operating system writes the file.

# Creating a New File

```js
const fs = require("fs");

fs.writeFile(
    "notes.txt",
    "Learning Node.js",
    (error) => {

        if (error) {

            console.log(error);

            return;

        }

        console.log("File Created");

    }
);
```

Output

```
File Created
```

# Writing JSON Data

```js
const fs = require("fs");

const user = {

    name: "Rahul",

    age: 22

};

fs.writeFile(

    "user.json",

    JSON.stringify(user, null, 2),

    (error) => {

        if (error) {

            console.log(error);

            return;

        }

        console.log("JSON Saved");

    }

);
```

---

# Error Handling

Always check the error first.

```js
fs.writeFile(

    "notes.txt",

    "Hello",

    (error) => {

        if (error) {

            console.error(error.message);

            return;

        }

        console.log("Success");

    }

);
```

# Best Practices

✅ Prefer `writeFile()` over `writeFileSync()` in servers.

✅ Always handle errors.

✅ Convert objects using `JSON.stringify()`.

✅ Use UTF-8 when writing text files.

---

# Common Mistakes

### Forgetting Error Handling

```js
fs.writeFile(

    "data.txt",

    "Hello",

    () => {

        console.log("Done");

    }

);
```

Always check the `error` argument.

---

### Writing Objects Directly

Incorrect

```js
fs.writeFile(

    "user.json",

    user,

    callback

);
```

Correct

```js
JSON.stringify(user)
```

---

### Expecting writeFile() to Block

`writeFile()` is asynchronous.

The next line executes immediately.

# API Comparison

| API | Style | Recommended |
|------|-------|-------------|
| `writeFileSync()` | Synchronous | Startup Scripts |
| `writeFile()` | Callback | Existing Projects |
| `fs.promises.writeFile()` | Promise | ✅ Modern Applications |

---

# Key Takeaways

- `fs.writeFile()` writes data asynchronously.
- JavaScript continues executing while the file is being written.
- Results are handled inside the callback function.
- It is preferred over `writeFileSync()` for backend servers.
- Always handle errors before assuming the file was written successfully.
