# Introduction

`fs.promises.access()` is the Promise-based version of `fs.access()`.

Instead of callbacks,

it returns a Promise.

This allows us to use `async/await`, making asynchronous code cleaner and easier to maintain.

It checks whether a file or directory can be accessed.

It **does not**

- Open the file
- Read the file
- Modify the file

It only checks permissions.

---

# Why fs.promises.access()?

Suppose your backend loads

```
config.json
```

when the server starts.

Before reading the file,

you want to verify

- Does it exist?
- Is it readable?
- Do I have permission?

`fs.promises.access()` performs these checks.

# Syntax

```js
await fs.access(path[, mode]);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| path | File or directory path |
| mode | Permission to check |

---

# Access Modes

| Constant | Meaning |
|----------|---------|
| `F_OK` | Path exists |
| `R_OK` | Read permission |
| `W_OK` | Write permission |
| `X_OK` | Execute permission |

Example

```js
const { constants } = require("fs");
```

---

# Return Value

Returns a Promise.

If access is allowed,

the Promise is resolved.

If access is denied,

the Promise is rejected.

No value is returned.

# Checking File Existence

```js
const fs = require("fs").promises;
const { constants } = require("fs");

async function main() {

    try {

        await fs.access(

            "notes.txt",

            constants.F_OK

        );

        console.log("File Exists");

    } catch {

        console.log("File Missing");

    }

}

main();
```

# Error Handling

Always use

```js
try...catch
```

```js
const fs = require("fs").promises;
const { constants } = require("fs");

async function main() {

    try {

        await fs.access(

            "missing.txt",

            constants.F_OK

        );

    } catch (error) {

        console.log(error.message);

    }

}

main();
```

# Best Practices

✅ Use `try...catch`.

✅ Check specific permissions (`R_OK`, `W_OK`).

✅ Prefer Promise APIs in modern applications.

❌ Don't use `access()` before every file operation.

---

# Common Mistakes

### Using access() Before readFile()

```js
await fs.access(file);

await fs.readFile(file);
```

This introduces a race condition.

Instead,

directly use

```js
await fs.readFile(file);
```

and handle any error.

---

### Assuming access() Opens the File

Incorrect.

It only checks permissions.

---

### Forgetting await

```js
fs.access(

    "notes.txt"
);

console.log("Done");
```

The Promise may still be pending.

---

# Notes

- `fs.promises.access()` checks permissions only.
- It does not read or open the file.
- It is useful for startup validation and permission checks.
- Avoid using it immediately before file operations due to race conditions.

---

# Key Takeaways

- `fs.promises.access()` is the modern way to check file accessibility.
- It works with `async/await`.
- It supports existence, read, write, and execute permission checks.
- It should not replace proper error handling on file operations.
- It is commonly used during application startup and permission validation.
