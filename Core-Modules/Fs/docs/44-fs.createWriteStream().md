# Introduction

`fs.createWriteStream()` creates a **Writable Stream**.

Instead of writing the entire data at once,

it writes data **chunk by chunk**.

This makes it suitable for writing

- Large files
- Logs
- Reports
- CSV exports
- Video downloads

---

# Why createWriteStream()?

Suppose your application generates

```
sales-report.csv

Size

3 GB
```

Using

```js
fs.writeFile()
```

Node.js first prepares the complete data in memory.

Only then does it write the file.

With

```js
createWriteStream()
```

Data is written immediately.

```
Application

↓

Chunk

↓

Disk

↓

Next Chunk

↓

Disk
```

Memory usage remains low.

# Writing Data

Example

```js
const fs = require("fs");

const stream = fs.createWriteStream(

    "notes.txt"

);

stream.write("Hello");

stream.write(" Node.js");

stream.end();
```

Output

```
Hello Node.js
```

---

# Important Methods

## write()

Writes one chunk.

```js
stream.write("Hello");
```

---

## end()

Signals that no more data will be written.

```js
stream.end();
```

After calling

```
end()
```

you should not call

```
write()
```

again.

---

# Important Events

### finish

Writing completed successfully.

```js
stream.on(

    "finish",

    () => {

        console.log("Done");

    }

);
```

---

### error

Writing failed.

```js
stream.on(

    "error",

    (error) => {

        console.log(error.message);

    }

);
```

---

### close

Underlying file descriptor has been closed.

# Options

Example

```js
const stream = fs.createWriteStream(

    "notes.txt",

    {

        flags: "a",

        encoding: "utf8",

        highWaterMark: 1024

    }

);
```

Common options

| Option | Purpose |
|---------|----------|
| flags | Write mode |
| encoding | Character encoding |
| highWaterMark | Internal buffer size |
| start | Start writing from a byte offset |

---

# flags

Most commonly used values

| Flag | Meaning |
|------|---------|
| w | Create or overwrite file |
| a | Append to existing file |
| wx | Create only if file does not exist |
| ax | Append only if file exists |

Example

```js
const stream = fs.createWriteStream(

    "logs.txt",

    {

        flags: "a"

    }

);
```

---

# HighWaterMark

Default

```
16 KB
```

Unlike `createReadStream()`, whose default is typically **64 KB** for file streams, the default writable highWaterMark for file write streams is **16 KB**.

Example

```js
const stream = fs.createWriteStream(

    "data.txt",

    {

        highWaterMark: 1024

    }

);
```

The stream buffers up to approximately

```
1 KB
```

before applying backpressure.

```js
const fs = require("fs");

```

# Real Project Example

Export user data into a CSV file.

```js
const fs = require("fs");

const stream = fs.createWriteStream(

    "users.csv"

);

stream.write("id,name\n");

stream.write("1,Amit\n");

stream.write("2,Rahul\n");

stream.end();

stream.on(

    "finish",

    () => {

        console.log("CSV Created");

    }

);
```

# Best Practices

✅ Always call `end()`.

✅ Listen for `finish`.

✅ Listen for `error`.

✅ Use streams for large output.

---

# Common Mistakes

### Forgetting end()

Without

```js
stream.end();
```

the stream may never finish properly.

---

### Writing After end()

Incorrect

```js
stream.end();

stream.write("Hello");
```

This throws an error.

---

### Ignoring finish

Use

```
finish
```

to know when writing is complete.

---

### Ignoring Backpressure

Calling

```js
write()
```

very rapidly without checking its return value can fill the internal buffer.

We'll learn how to handle this properly in the **Backpressure** chapter.

# Key Takeaways

- `fs.createWriteStream()` writes data chunk by chunk.
- It is ideal for generating large files.
- Call `end()` after writing the final chunk.
- Listen for `finish` and `error` events.
- It is commonly used for logs, reports, downloads, and large file generation.
