# Introduction

`fs.promises.unlink()` is the Promise-based version of `fs.unlink()`.

Instead of callbacks,

it returns a Promise.

This allows us to use `async/await`, making asynchronous code cleaner and easier to maintain.

It permanently deletes a file from the file system.

It **cannot** delete directories.

---

# Why fs.promises.unlink()?

Suppose a user uploads a new profile picture.

```
uploads/

├── old-profile.png

└── new-profile.png
```

After saving the new image successfully,

the old image is no longer needed.

Your application deletes it using

```js
await fs.unlink(...)
```

without blocking the server.

# Return Value

Returns a Promise.

If the deletion succeeds,

the Promise is resolved.

If an error occurs,

the Promise is rejected.

The method does not return any value.

# Error Handling

Always use

```js
try...catch
```

```js
const fs = require("fs").promises;

async function main() {

    try {

        await fs.unlink(

            "notes.txt"

        );

        console.log("Deleted");

    } catch (error) {

        console.log(error.message);

    }

}

main();
```

---

# Real Project Example

Suppose Multer stores uploaded images.

When the user updates the profile picture,

delete the old image.

```js
const fs = require("fs").promises;

async function updateProfile() {

    try {

        await fs.unlink(

            "uploads/old-profile.png"

        );

        console.log("Old Image Deleted");

    } catch (error) {

        if (error.code !== "ENOENT") {

            throw error;

        }

    }

}
```

If the old image is already missing,

the application continues normally.

# Best Practices

✅ Prefer Promise APIs in modern applications.

✅ Always use `try...catch`.

✅ Ignore only `ENOENT` when cleanup should be idempotent.

✅ Verify file paths before deleting.

---

# Common Mistakes

### Forgetting await

```js
fs.unlink("notes.txt");

console.log("Done");
```

The delete operation may still be running.

---

### Trying to Delete a Directory

```js
await fs.unlink(

    "uploads"

);
```

This throws an error.

Use

```js
await fs.rm(

    "uploads",

    {

        recursive: true

    }

);
```

---

### Ignoring Errors

Always handle Promise rejections.

# Notes

- `fs.promises.unlink()` deletes only files.
- It cannot remove directories.
- It returns a Promise.
- Handle errors using `try...catch`.
- Ignore `ENOENT` only when repeated cleanup is acceptable.

---

# Key Takeaways

- `fs.promises.unlink()` permanently deletes a file asynchronously.
- It works with `async/await`.
- It cannot delete directories.
- It is commonly used for upload cleanup, cache cleanup, log rotation, and temporary file removal.
- It is the recommended API for modern Node.js applications.
