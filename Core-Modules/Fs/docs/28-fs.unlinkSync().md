# Introduction

`fs.unlinkSync()` is the synchronous version of `fs.unlink()`.

It permanently deletes a file from the file system.

Unlike `fs.rmSync()`,

this API is designed only for deleting files.

JavaScript waits until the file has been deleted before executing the next line.

---

# Why unlinkSync()?

Suppose a user changes their profile picture.

Old Structure

```
uploads/

├── old-profile.png

└── new-profile.png
```

After successfully saving the new image,

the old image is no longer needed.

The application deletes it using

```js
fs.unlinkSync()
```

---

# Syntax

```js
fs.unlinkSync(path);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| path | Path of the file to delete |

---

# Return Value

`fs.unlinkSync()` returns

```js
undefined
```

If the operation fails,

Node.js throws an Error.

# Error Handling

Always wrap synchronous APIs inside

```js
try...catch
```

```js
const fs = require("fs");

try {

    fs.unlinkSync("notes.txt");

    console.log("Deleted");

} catch (error) {

    console.log(error.message);

}
```

---

# Common Error Codes

| Error Code | Meaning |
|------------|---------|
| ENOENT | File does not exist |
| EACCES | Permission denied |
| EPERM | Operation not permitted |
| EISDIR | The given path is a directory, not a file |

# Best Practices

✅ Always use `try...catch`.

✅ Verify the file exists before deleting it when appropriate.

✅ Delete temporary files after use.

✅ Prefer Promise APIs in modern backend applications.

---

# Common Mistakes

### Trying to Delete a Directory

```js
fs.unlinkSync("uploads");
```

This throws an error because `unlinkSync()` deletes **files only**.

To remove directories, use

```js
fs.rmSync()
```

---

### Deleting the Wrong File

Always verify the file path before deleting.

Deletion is permanent.

---

### Forgetting try...catch

Synchronous APIs throw errors directly.

Always handle them.

---

# Notes

- `unlinkSync()` deletes **only files**.
- It cannot delete directories.
- Deleted files cannot be recovered using the FS API.
- Always verify the file path before deleting.
- Use `try...catch` with synchronous APIs.

---

# Key Takeaways

- `fs.unlinkSync()` permanently deletes a file.
- It blocks JavaScript until the deletion is complete.
- It throws an error if the file does not exist or if the path points to a directory.
- Use it for startup scripts, CLI tools, and local automation.
- Prefer Promise-based APIs in modern backend applications.
