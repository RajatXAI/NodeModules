# Introduction

`fs.access()` checks whether your application can access a file or directory.

It does **not** open the file.

It does **not** read the file.

It simply asks the operating system

> "Can I access this file with the requested permission?"

The operation runs asynchronously.

---

# Why access()?

Suppose your application wants to read

```
config.json
```

Instead of directly reading the file,

you first want to know

- Does it exist?
- Can it be read?
- Do I have permission?

This helps prevent unnecessary errors.

---

# Syntax

```js
fs.access(path[, mode], callback);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| path | File or directory path |
| mode | Permission to check |
| callback | Runs after the check completes |

---

# Access Modes

Node.js provides four modes.

| Constant | Meaning |
|----------|---------|
| `fs.constants.F_OK` | Path exists (default) |
| `fs.constants.R_OK` | Read permission |
| `fs.constants.W_OK` | Write permission |
| `fs.constants.X_OK` | Execute permission |

---

# Callback Function

```js
(error) => {

}
```

If access is allowed

```js
error
```

is

```js
null
```

Otherwise,

it contains an Error object.

---

# Return Value

```js
undefined
```

The result is available inside the callback.

# Checking File Existence

```js
const fs = require("fs");

fs.access(

    "notes.txt",

    fs.constants.F_OK,

    (error) => {

        if (error) {

            console.log("File does not exist");

            return;

        }

        console.log("File exists");

    }

);
```

---

# Checking Read Permission

```js
const fs = require("fs");

fs.access(

    "notes.txt",

    fs.constants.R_OK,

    (error) => {

        if (error) {

            console.log("Cannot read file");

            return;

        }

        console.log("Readable");

    }

);
```

# Error Handling

```js
const fs = require("fs");

fs.access(

    "missing.txt",

    fs.constants.F_OK,

    (error) => {

        if (error) {

            console.log(error.message);

            return;

        }

        console.log("Accessible");

    }

);
```

---

# Common Error Codes

| Error Code | Meaning |
|------------|---------|
| ENOENT | File or directory does not exist |
| EACCES | Permission denied |
| EPERM | Operation not permitted |

# Real Project Example

Suppose your backend stores logs inside

```
logs/
```

Before writing logs,

verify that the directory exists.

```js
const fs = require("fs");

fs.access(

    "logs",

    fs.constants.F_OK,

    (error) => {

        if (error) {

            console.log("Logs folder missing");

            return;

        }

        console.log("Logs folder exists");

    }

);
```

# Best Practices

✅ Use `access()` to check permissions.

✅ Use specific modes like `R_OK` or `W_OK`.

✅ Prefer Promise APIs in modern applications.

❌ Don't use `access()` just to check if you'll immediately open the file.

---

# Common Mistakes

### Using access() Before Every readFile()

```js
fs.access(...);

fs.readFile(...);
```

This is unnecessary.

The file might change between the two operations.

Instead,

call

```js
fs.readFile()
```

directly and handle the error.

---

### Assuming access() Opens the File

Incorrect.

It only checks permissions.

---

### Ignoring Errors

Always handle callback errors.

---

# Notes

- `access()` checks permissions only.
- It does not open or read the file.
- Don't use it as a replacement for proper error handling.
- Handle errors from the actual operation (`readFile`, `writeFile`, etc.).

---

# Key Takeaways

- `fs.access()` checks whether a file or directory can be accessed.
- It supports checking existence, read, write, and execute permissions.
- It is asynchronous and callback-based.
- It should not replace proper error handling on the actual file operation.
- It is useful for permission validation and startup checks.
