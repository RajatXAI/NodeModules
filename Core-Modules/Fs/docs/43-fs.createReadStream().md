# Introduction

`fs.createReadStream()` creates a **Readable Stream**.

Instead of loading the entire file into memory,

it reads the file **chunk by chunk**.

This makes it ideal for

- Large files
- Video streaming
- File downloads
- CSV processing
- Log analysis

---

# Why createReadStream()?

Imagine a file

```
movie.mp4

Size

10 GB
```

Using

```js
fs.readFile()
```

Node.js first loads

```
10 GB

↓

RAM
```

Only then can processing begin.

Using

```js
createReadStream()
```

Flow

```
Disk

↓

64 KB

↓

Application

↓

Next 64 KB

↓

Application
```

Processing starts immediately.

# Basic Example

```js
const fs = require("fs");

const stream = fs.createReadStream(

    "notes.txt"

);

stream.on("data", (chunk) => {

    console.log(chunk);

});

stream.on("end", () => {

    console.log("Finished");

});
```

# Options

Example

```js
const stream = fs.createReadStream(

    "notes.txt",

    {

        encoding: "utf8",

        highWaterMark: 1024

    }

);
```

Common options

| Option | Purpose |
|---------|----------|
| encoding | Convert Buffer into string |
| highWaterMark | Chunk size |
| start | Start reading from a specific byte |
| end | Stop reading at a specific byte |

---

# HighWaterMark

Default

```
64 KB
```

Example

```js
const stream = fs.createReadStream(

    "notes.txt",

    {

        highWaterMark: 1024

    }

);
```

Now,

Node.js reads

```
1 KB

↓

1 KB

↓

1 KB
```

instead of

```
64 KB
```

**Note:**

`highWaterMark` controls the **maximum amount of data Node.js tries to read into its internal buffer at a time.** It is a size limit, **not a guarantee** that every emitted chunk will be exactly that size.

# Real Project Example

Imagine a backend where users upload log files of several gigabytes.

Instead of loading the whole file,

process it line by line.

```js
const fs = require("fs");

const stream = fs.createReadStream(

    "server.log",

    {

        encoding: "utf8"

    }

);

stream.on("data", (chunk) => {

    console.log(

        "Received:",

        chunk.length,

        "characters"

    );

});

stream.on("end", () => {

    console.log("Log Processing Completed");

});
```

# Best Practices

✅ Use Streams for large files.

✅ Always handle the `error` event.

✅ Use encoding when reading text files.

✅ Close resources automatically by handling stream completion.

---

# Common Mistakes

### Using readFile() for Huge Files

```js
fs.readFile(

    "movie.mp4"

);
```

This loads the complete file into memory.

Use

```js
createReadStream()
```

instead.

---

### Forgetting error

```js
stream.on("data", ...);
```

Always add

```js
stream.on("error", ...);
```

---

### Assuming Every Chunk Is Exactly 64 KB

Chunk size may vary.

The last chunk is usually smaller.

Even earlier chunks can differ depending on the operating system and stream state.

---

### Forgetting end

Without handling

```
end
```

you don't know when reading has finished.

# Key Takeaways

- `fs.createReadStream()` reads files chunk by chunk.
- It is ideal for large files because it avoids loading the entire file into memory.
- It emits events such as `data`, `end`, `error`, and `close`.
- `highWaterMark` controls the internal buffer size used while reading.
- It is the foundation of file streaming, downloads, uploads, and many production systems.
