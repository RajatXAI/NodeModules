# Introduction

`fs.copyFile()` is the asynchronous version of `fs.copyFileSync()`.

It copies a file from one location to another without blocking JavaScript execution.

Unlike `fs.rename()`,

the original file remains unchanged.

When the copy operation finishes,

the callback function is executed.

---

# Why copyFile()?

Imagine a server that creates backups for uploaded files.

```
uploads/

↓

Copy File

↓

backup/
```

While the file is being copied,

the server can continue handling other incoming requests.

---

# Syntax

```js
fs.copyFile(src, dest[, mode], callback);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| src | Source file path |
| dest | Destination file path |
| mode | Optional copy mode |
| callback | Function executed after copying |

---

# Callback Function

The callback receives one argument.

```js
(error) => {

}
```

If the operation succeeds,

```js
error
```

is

```js
null
```

Otherwise,

it contains an Error object.

---

# Return Value

`fs.copyFile()` returns

```js
undefined
```

The result is available inside the callback.

# Copying a File

# Copy Modes

Prevent overwriting an existing file.

```js
const fs = require("fs");

fs.copyFile(

    "a.txt",

    "b.txt",

    fs.constants.COPYFILE_EXCL,

    (error) => {

        if (error) {

            console.log(error.message);

            return;

        }

        console.log("Copied");

    }

);
```

If

```
b.txt
```

already exists,

Node.js throws an error.

---

# Error Handling

Always check the error first.

```js
const fs = require("fs");

fs.copyFile(

    "source.txt",

    "backup.txt",

    (error) => {

        if (error) {

            console.log(error.message);

            return;

        }

        console.log("Success");

    }

);
```

---

# Common Error Codes

| Error Code | Meaning |
|------------|---------|
| ENOENT | Source file does not exist |
| EACCES | Permission denied |
| EPERM | Operation not permitted |
| EEXIST | Destination already exists (with `COPYFILE_EXCL`) |

# Best Practices

✅ Always check the error.

✅ Verify that the source file exists.

✅ Use `COPYFILE_EXCL` to avoid accidental overwriting.

✅ Prefer Promise APIs in modern backend applications.

---

# Common Mistakes

### Thinking copyFile() Removes the Original File

Incorrect.

The original file always remains.

---

### Destination Directory Does Not Exist

```js
fs.copyFile(

    "a.txt",

    "backup/files/a.txt",

    callback

);
```

If

```
backup/files/
```

does not exist,

the operation fails.

Create the directory first.

---

### Ignoring Errors

Always check the callback error.

# Key Takeaways

- `fs.copyFile()` copies files asynchronously.
- The original file remains unchanged.
- JavaScript continues executing while the copy operation runs.
- Use `COPYFILE_EXCL` to prevent accidental overwriting.
- Always check the callback error before assuming the copy succeeded.
