# Introduction

`fs.rmSync()` is the synchronous version of `fs.rm()`.

It can delete

- Files
- Empty directories
- Non-empty directories (using `recursive: true`)

Unlike `fs.unlinkSync()`,

this API is **not limited to files**.

JavaScript waits until the deletion is complete before executing the next line.

---

# unlink() vs rm()

| Feature | unlinkSync() | rmSync() |
|----------|--------------|-----------|
| Delete File | ✅ | ✅ |
| Delete Empty Directory | ❌ | ✅ |
| Delete Non-empty Directory | ❌ | ✅ (`recursive: true`) |

---

# Why rmSync()?

Suppose your application creates temporary folders.

```
temp/

├── image1.png

├── image2.png

└── logs/
```

After processing,

the entire folder should be removed.

Instead of deleting every file one by one,

Node.js can delete the complete directory.

---

# Syntax

```js
fs.rmSync(path[, options]);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| path | File or directory path |
| options | Configuration object |

---

# Return Value

`fs.rmSync()` returns

```js
undefined
```

If something goes wrong,

Node.js throws an Error.

---

# Internal Working

```
Application

↓

FS Module

↓

Operating System

↓

Locate File / Directory

↓

Delete

↓

Return Control

↓

Continue Execution
```

JavaScript waits until the deletion finishes.

# Deleting a Directory Recursively

Before

```
project/

└── uploads/

    ├── image.jpg

    ├── notes.txt

    └── profile/

        └── avatar.png
```

Code

```js
const fs = require("fs");

fs.rmSync(

    "uploads",

    {

        recursive: true

    }

);
```

After

```
project/
```

Everything inside the directory is deleted.

---

# Force Option

Sometimes you do not want an error if the file or directory does not exist.

Use

```js
force: true
```

```js
const fs = require("fs");

fs.rmSync(

    "temp",

    {

        recursive: true,

        force: true

    }

);
```

If

```
temp/
```

does not exist,

Node.js does not throw an error.

---

# Error Handling

```js
const fs = require("fs");

try {

    fs.rmSync(

        "uploads",

        {

            recursive: true

        }

    );

} catch (error) {

    console.log(error.message);

}
```

---

# Common Error Codes

| Error Code | Meaning |
|------------|---------|
| ENOENT | Path does not exist |
| EACCES | Permission denied |
| EPERM | Operation not permitted |
| ENOTEMPTY | Directory is not empty (without `recursive: true`) |

# Real Project Example

Suppose an image processing service creates temporary files.

```
temp/

├── resized.jpg

├── compressed.jpg

└── thumbnail.jpg
```

After all images are uploaded,

remove the entire folder.

```js
const fs = require("fs");

try {

    fs.rmSync(

        "temp",

        {

            recursive: true,

            force: true

        }

    );

    console.log("Temporary Folder Removed");

} catch (error) {

    console.log(error.message);

}
```

# Best Practices

✅ Use `recursive: true` only when you really want to delete everything.

✅ Use `force: true` for cleanup scripts.

✅ Always use `try...catch`.

✅ Prefer Promise APIs in modern applications.

---

# Common Mistakes

### Forgetting recursive

```js
fs.rmSync("uploads");
```

If

```
uploads/
```

contains files,

Node.js throws an error.

---

### Accidentally Deleting Important Data

```js
fs.rmSync(

    "uploads",

    {

        recursive: true

    }

);
```

Be careful.

This permanently removes everything.

---

### Using rmSync() in Express Routes

Avoid blocking the event loop.

Use Promise APIs instead.

# Notes

- `rmSync()` can delete both files and directories.
- Use `recursive: true` for non-empty directories.
- Use `force: true` to ignore missing paths.
- Deletion is permanent.
- Always double-check the path before deleting recursively.

---

# Key Takeaways

- `fs.rmSync()` is a powerful API for deleting files and directories.
- It replaces many older directory deletion use cases.
- `recursive: true` removes the entire directory tree.
- `force: true` is useful for cleanup scripts.
- Handle errors using `try...catch`.
