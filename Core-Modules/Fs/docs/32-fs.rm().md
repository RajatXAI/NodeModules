# Introduction

`fs.rm()` is the asynchronous version of `fs.rmSync()`.

It can delete

- Files
- Empty directories
- Non-empty directories (using `recursive: true`)

Unlike `fs.unlink()`,

this API is not limited to files.

JavaScript continues executing while the delete operation runs in the background.

When the operation finishes,

the callback function is executed.

---

# unlink() vs rm()

| Feature | unlink() | rm() |
|----------|----------|------|
| Delete File | ✅ | ✅ |
| Delete Empty Directory | ❌ | ✅ |
| Delete Non-empty Directory | ❌ | ✅ (`recursive: true`) |

---

# Why rm()?

Suppose your application creates a temporary folder.

```
temp/

├── image.jpg

├── report.pdf

└── thumbnails/

    └── thumb.png
```

After processing,

the entire folder should be removed.

Instead of deleting every file manually,

Node.js can delete the whole directory asynchronously.

---

# Syntax

```js
fs.rm(path[, options], callback);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| path | File or directory path |
| options | Configuration object |
| callback | Function executed after deletion |

---

# Callback Function

The callback receives one argument.

```js
(error) => {

}
```

If the operation succeeds,

```js
error
```

is

```js
null
```

Otherwise,

it contains an Error object.

---

# Return Value

`fs.rm()` returns

```js
undefined
```

The result is available inside the callback.

# Deleting a File

```js
const fs = require("fs");

fs.rm(

    "notes.txt",

    (error) => {

        if (error) {

            console.log(error);

            return;

        }

        console.log("File Deleted");

    }

);
```

---

# Deleting a Directory Recursively

Project

```
uploads/

├── image.jpg

├── notes.txt

└── profile/

    └── avatar.png
```

Code

```js
const fs = require("fs");

fs.rm(

    "uploads",

    {

        recursive: true

    },

    (error) => {

        if (error) {

            console.log(error);

            return;

        }

        console.log("Directory Deleted");

    }

);
```

Everything inside

```
uploads/
```

is removed.

---

# Force Option

```js
const fs = require("fs");

fs.rm(

    "temp",

    {

        recursive: true,

        force: true

    },

    (error) => {

        if (error) {

            console.log(error);

            return;

        }

        console.log("Cleanup Completed");

    }

);
```

If

```
temp/
```

does not exist,

no error is thrown.

---

# Error Handling

Always check the callback error.

```js
const fs = require("fs");

fs.rm(

    "uploads",

    {

        recursive: true

    },

    (error) => {

        if (error) {

            console.log(error.message);

            return;

        }

        console.log("Success");

    }

);
```

---

# Common Error Codes

| Error Code | Meaning |
|------------|---------|
| ENOENT | Path does not exist |
| EACCES | Permission denied |
| EPERM | Operation not permitted |
| ENOTEMPTY | Directory is not empty (without `recursive: true`) |

# Best Practices

✅ Use `recursive: true` only when required.

✅ Use `force: true` for cleanup scripts.

✅ Always check the callback error.

✅ Prefer Promise APIs in modern applications.

---

# Common Mistakes

### Forgetting recursive

```js
fs.rm(

    "uploads",

    callback

);
```

If the directory contains files,

the operation fails.

---

### Assuming force Deletes Everything

`force: true` only ignores missing-path errors.

It does **not** ignore permission errors.

---

### Using rm() for Individual Files Without Need

For deleting only files,

`unlink()` is also a valid choice.

Use `rm()` when you want one API that works for both files and directories.

# Notes

- `rm()` can delete both files and directories.
- Use `recursive: true` to remove non-empty directories.
- Use `force: true` when cleanup should ignore missing paths.
- Always check the callback error.
- Prefer Promise APIs in new projects.

---

# Key Takeaways

- `fs.rm()` is a flexible API for deleting both files and directories.
- It runs asynchronously and does not block JavaScript.
- `recursive: true` deletes an entire directory tree.
- `force: true` is useful for cleanup operations.
- It is recommended over older directory removal APIs.
