# Introduction

`fs.watch()` allows your application to monitor files and directories.

Whenever a file changes,

Node.js immediately notifies your application.

Unlike

```
readFile()
```

which reads a file once,

`watch()`

keeps listening for future changes.

---

# Why watch()?

Imagine you are building

```
nodemon
```

When

```
server.js
```

changes,

the server should restart automatically.

Instead of checking every second,

Node.js waits for the operating system to report a change.

---

# Syntax

```js
fs.watch(filename[, options][, listener]);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| filename | File or directory to monitor |
| options | Optional configuration |
| listener | Callback executed when a change occurs |

---

# Callback Function

```js
(eventType, filename) => {

}
```

### eventType

Possible values

```
rename
```

or

```
change
```

---

### filename

The name of the file that triggered the event.

Sometimes,

depending on the operating system,

it may be

```js
null
```

Always handle this case.

---

# Return Value

Returns

```js
FSWatcher
```

This object allows you to stop watching later.

---

# Internal Working

```
Application

↓

FS Module

↓

Operating System

↓

File System Events

↓

Event Queue

↓

Event Loop

↓

Execute Callback
```

Node.js does **not** continuously scan the file.

It receives notifications from the operating system.

# Watching a File

Project

```
project/

├── app.js

└── notes.txt
```

Code

```js
const fs = require("fs");

fs.watch(

    "notes.txt",

    (eventType, filename) => {

        console.log(eventType);

        console.log(filename);

    }

);
```

If

```
notes.txt
```

is edited,

Output

```
change

notes.txt
```

---

# Watching a Directory

```js
const fs = require("fs");

fs.watch(

    "uploads",

    (eventType, filename) => {

        console.log(eventType);

        console.log(filename);

    }

);
```

Whenever a file inside

```
uploads/
```

changes,

the callback executes.

---

# Event Types

### change

Occurs when

- File content changes
- File is modified

---

### rename

Occurs when

- File renamed
- File deleted
- New file created (in many systems)

Remember

```
rename
```

does **not always mean**

the file was renamed.

It can represent several filesystem events depending on the operating system.

---

# Closing a Watcher

```js
const fs = require("fs");

const watcher = fs.watch(

    "notes.txt",

    () => {

        console.log("Changed");

    }

);

watcher.close();
```

After calling

```js
close()
```

Node.js stops listening.

---

# Error Handling

```js
const fs = require("fs");

try {

    const watcher = fs.watch(

        "missing.txt",

        () => {}

    );

} catch (error) {

    console.log(error.message);

}
```

# Platform Differences

`fs.watch()` behaves differently on different operating systems.

For example,

- Windows
- Linux
- macOS

may generate different event sequences.

Do not rely on

```
rename
```

always meaning "file renamed."

# Best Practices

✅ Always store the watcher instance.

✅ Close watchers when no longer needed.

✅ Handle `filename === null`.

✅ Test on your target operating system.

---

# Common Mistakes

### Assuming rename Means Rename

Incorrect.

It may indicate

- Rename
- Delete
- Create

depending on the platform.

---

### Forgetting to Close Watchers

Unused watchers consume system resources.

Always call

```js
watcher.close()
```

when finished.

---

### Watching Thousands of Files

Watching every file individually can consume significant system resources.

Prefer watching directories when appropriate.

# Notes

- `fs.watch()` listens for real-time filesystem events.
- It depends on operating system notifications.
- Event names may differ across platforms.
- Always close unused watchers.
- It is widely used in development tools like Nodemon and Vite.

---

# Key Takeaways

- `fs.watch()` monitors files and directories for changes.
- It returns an `FSWatcher` object.
- You can stop monitoring using `watcher.close()`.
- Event behavior varies across operating systems.
- It is the foundation of many modern development tools.
