# Introduction

`fs.promises.copyFile()` is the Promise-based version of `fs.copyFile()`.

Instead of callbacks,

it returns a Promise.

This allows us to use `async/await`, making asynchronous code easier to read and maintain.

Unlike `rename()`,

the original file remains unchanged after copying.

---

# Why fs.promises.copyFile()?

Suppose your backend receives an uploaded image.

Before resizing it,

you want to create a backup.

```
uploads/

↓

Copy Image

↓

backup/

↓

Resize Original
```

The backup remains available even if image processing fails.

# Syntax

```js
await fs.copyFile(src, dest[, mode]);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| src | Source file path |
| dest | Destination file path |
| mode | Optional copy mode |

---

# Return Value

Returns a Promise.

If the operation succeeds,

the Promise is resolved.

If an error occurs,

the Promise is rejected.

The method itself does not return any value.

# Copy Modes

Node.js provides optional copy modes.

The most common one is

```js
fs.constants.COPYFILE_EXCL
```

Example

```js
const fs = require("fs").promises;
const { constants } = require("fs");

async function main() {

    await fs.copyFile(

        "a.txt",

        "b.txt",

        constants.COPYFILE_EXCL

    );

}

main();
```

If

```
b.txt
```

already exists,

Node.js throws an error instead of overwriting it.

---

# Error Handling

Always use

```js
try...catch
```

```js
const fs = require("fs").promises;

async function main() {

    try {

        await fs.copyFile(

            "source.txt",

            "backup.txt"

        );

        console.log("Copied");

    } catch (error) {

        console.log(error.message);

    }

}

main();
```

---

# Common Error Codes

| Error Code | Meaning |
|------------|---------|
| ENOENT | Source file does not exist |
| EACCES | Permission denied |
| EPERM | Operation not permitted |
| EEXIST | Destination already exists (with `COPYFILE_EXCL`) |

# Best Practices

✅ Prefer Promise APIs in modern applications.

✅ Always use `try...catch`.

✅ Verify that the source file exists.

✅ Use `COPYFILE_EXCL` to avoid accidental overwriting.

---

# Common Mistakes

### Forgetting await

```js
fs.copyFile(

    "a.txt",

    "b.txt"

);

console.log("Done");
```

The copy operation may still be running.

---

### Destination Directory Does Not Exist

```js
await fs.copyFile(

    "a.txt",

    "backup/files/a.txt"

);
```

If

```
backup/files/
```

does not exist,

Node.js throws an error.

Create the directory first.

---

### Thinking copyFile() Moves the File

Incorrect.

The original file remains unchanged.

---

### Ignoring Errors

Always handle Promise rejections using `try...catch`.

# Key Takeaways

- `fs.promises.copyFile()` copies a file without modifying the original.
- It returns a Promise and works with `async/await`.
- Use `COPYFILE_EXCL` to prevent overwriting an existing file.
- Always handle errors using `try...catch`.
- It is commonly used for backups, templates, image processing, and caching.
