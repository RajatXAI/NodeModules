# Introduction

`fs.unlink()` is the asynchronous version of `fs.unlinkSync()`.

It permanently deletes a file without blocking JavaScript execution.

While the file is being deleted,

Node.js can continue handling other tasks.

When the deletion completes,

the callback function is executed.

---

# Why unlink()?

Suppose a user uploads a new profile picture.

```
uploads/

├── old-profile.png

└── new-profile.png
```

After the new image is saved successfully,

the old image should be removed.

Instead of blocking the server,

Node.js deletes the file asynchronously.

---

# Syntax

```js
fs.unlink(path, callback);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| path | File path |
| callback | Function executed after deletion |

---

# Callback Function

The callback receives one argument.

```js
(error) => {

}
```

If the operation succeeds,

```js
error
```

is

```js
null
```

Otherwise,

it contains an Error object.

---

# Return Value

`fs.unlink()` returns

```js
undefined
```

The result is available inside the callback.

# Deleting a File

```js

fs.unlink(

    "notes.txt",

            console.log(error);

        console.log("File Deleted");

    }

);
```

```
project/
```

# Error Handling

Always check the error first.

```js
const fs = require("fs");

fs.unlink(

    "notes.txt",

    (error) => {

        if (error) {

            console.log(error.message);

            return;

        }

        console.log("Deleted");

    }

);
```

---

# Common Error Codes

| Error Code | Meaning |
|------------|---------|
| ENOENT | File does not exist |
| EACCES | Permission denied |
| EPERM | Operation not permitted |
| EISDIR | The path is a directory, not a file |

# Best Practices

✅ Always check the callback error.

✅ Delete temporary files after they are no longer needed.

✅ Verify file paths before deletion.

✅ Prefer Promise APIs in modern backend applications.

---

# Common Mistakes

### Trying to Delete a Directory

```js
fs.unlink(

    "uploads",

    callback

);
```

This throws an error because `unlink()` deletes only files.

Use

```js
fs.rm()
```

to remove directories.

---

### Ignoring Errors

Always handle

- Missing files
- Permission errors
- Invalid paths

---

### Assuming unlink() Blocks Execution

It is asynchronous.

The next line executes immediately.

# Notes

- `unlink()` deletes only files.
- It cannot remove directories.
- The operation runs asynchronously.
- Always check the callback error.
- Use Promise APIs for new projects.

---

# Key Takeaways

- `fs.unlink()` deletes files asynchronously.
- JavaScript continues executing while the deletion is in progress.
- The callback is executed after the operation completes.
- It cannot delete directories.
- Always handle errors before assuming the file was deleted.
