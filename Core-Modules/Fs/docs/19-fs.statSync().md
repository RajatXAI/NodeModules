# Introduction

`fs.statSync()` is the synchronous version of `fs.stat()`.

It does **not** read the contents of a file.

Instead, it returns **metadata** about a file or directory.

Metadata means information *about* the file, not the file's actual content.

For example,

- File size
- Creation date
- Last modified date
- Last accessed date
- Is it a file?
- Is it a directory?

---

# Why statSync()?

Suppose a user uploads a file.

Before saving it, you want to check

- Is this actually a file?
- Is the file size less than 5 MB?
- Does the path exist?

Instead of reading the entire file,

Node.js can return its metadata using `statSync()`.

---

# Syntax

```js
fs.statSync(path[, options]);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| path | File or directory path |
| options | Optional configuration |

---

# Return Value

Returns a **Stats** object.

Example

```js
Stats {
    size: 2048,
    birthtime: ...,
    mtime: ...,
    ...
}
```

If the path does not exist,

Node.js throws an Error.

---

# What Information Does statSync() Provide?

The returned `Stats` object contains many useful properties.

| Property | Description |
|----------|-------------|
| size | File size in bytes |
| birthtime | Creation time |
| mtime | Last modified time |
| atime | Last accessed time |
| ctime | Metadata change time |

It also provides useful methods.

| Method | Purpose |
|---------|----------|
| isFile() | Checks whether the path is a file |
| isDirectory() | Checks whether the path is a directory |

# Error Handling

Always use

```js
try...catch
```

```js
const fs = require("fs");

try {

    const stats = fs.statSync(

        "missing.txt"

    );

    console.log(stats);

} catch (error) {

    console.log(error.message);

}
```

Example Output

```
ENOENT: no such file or directory
```

# Best Practices

✅ Use `try...catch`.

✅ Use `isFile()` before reading a file.

✅ Validate file size before processing uploads.

✅ Prefer Promise APIs in modern backend applications.

---

# Common Mistakes

### Confusing statSync() with readFileSync()

`statSync()` returns **metadata**, not the file content.

---

### Assuming Every Path Is a File

Always check

```js
stats.isFile()
```

or

```js
stats.isDirectory()
```

---

### Ignoring Errors

Always handle missing paths using `try...catch`.

# Key Takeaways

- `fs.statSync()` returns metadata about a file or directory.
- It does **not** read the file contents.
- The returned `Stats` object contains properties like `size`, `birthtime`, `mtime`, and methods like `isFile()` and `isDirectory()`.
- Use `try...catch` because synchronous APIs throw errors directly.
- It is commonly used for file validation, backup systems, and file explorers.
