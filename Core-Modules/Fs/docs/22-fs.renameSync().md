# Introduction

`fs.renameSync()` is the synchronous version of `fs.rename()`.

It is used to

- Rename files
- Rename directories
- Move files
- Move directories

JavaScript waits until the operation completes before executing the next line.

---

# Why renameSync()?

Suppose a user uploads

```
abc123.png
```

After processing,

you want to rename it as

```
profile.png
```

or move it from

```
uploads/
```

to

```
images/
```

Both operations can be performed using

```js
fs.renameSync()
```

---

# Syntax

```js
fs.renameSync(oldPath, newPath);
```

---

# Parameters

| Parameter | Description |
|-----------|-------------|
| oldPath | Current file or directory path |
| newPath | New file or directory path |

---

# Return Value

`fs.renameSync()` returns

```js
undefined
```

If an error occurs,

Node.js throws an Error.

# Renaming a File

Before

```
project/

└── notes.txt
```

Code

```js
const fs = require("fs");

fs.renameSync(

    "notes.txt",

    "tasks.txt"

);

console.log("Renamed");
```

After

```
project/

└── tasks.txt
```

---

# Renaming a Directory

Before

```
uploads/
```

Code

```js
const fs = require("fs");

fs.renameSync(

    "uploads",

    "images"

);
```

After

```
images/
```

# Moving Files

Suppose

```
project/

├── uploads/

│   └── photo.jpg

└── images/
```

Code

```js
const fs = require("fs");

fs.renameSync(

    "uploads/photo.jpg",

    "images/photo.jpg"

);
```

Result

```
project/

├── uploads/

└── images/

    └── photo.jpg
```

The file is moved to the new folder.

---

# Moving Directories

```js
const fs = require("fs");

fs.renameSync(

    "uploads",

    "backup/uploads"

);
```

The entire directory is moved.

---

# Error Handling

Always use

```js
try...catch
```

```js
const fs = require("fs");

try {

    fs.renameSync(

        "missing.txt",

        "new.txt"

    );

} catch (error) {

    console.log(error.message);

}
```

---

# Common Error Codes

| Error Code | Meaning |
|------------|---------|
| ENOENT | Source file or directory does not exist |
| EACCES | Permission denied |
| EPERM | Operation not permitted |
| ENOTDIR | Expected a directory but found a file |
| EISDIR | Expected a file but found a directory |

# Best Practices

✅ Always use `try...catch`.

✅ Verify that the source path exists.

✅ Use meaningful file names.

✅ Prefer Promise APIs in modern backend applications.

---

# Common Mistakes

### Source File Does Not Exist

```js
fs.renameSync(

    "missing.txt",

    "new.txt"

);
```

Throws

```
ENOENT
```

---

### Assuming renameSync() Only Renames

It can also move files and directories.

---

### Using renameSync() Inside API Routes

Avoid blocking the event loop.

Use Promise APIs instead.

# Key Takeaways

- `fs.renameSync()` can rename both files and directories.
- It can also move files and directories by changing the destination path.
- JavaScript waits until the operation completes.
- Always use `try...catch` with synchronous APIs.
- Prefer Promise-based APIs for modern backend applications.
