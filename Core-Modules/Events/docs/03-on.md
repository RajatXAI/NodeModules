# Introduction

The `.on()` method is used to register a listener for an event.

Basic idea:

```text
.on()

↓

"Whenever this event happens,

run this function."
```

Example:

```js
emitter.on("login", () => {

    console.log("User logged in");

});
```

The callback does **not** execute when `.on()` is called.

It only gets registered.

---

# What is `.on()`?

`.on()` is a method provided by `EventEmitter`.

It tells the EventEmitter:

> "Listen for this event and execute this listener whenever the event is emitted."

Example:

```js
emitter.on("message", listener);
```

Flow:

```text
Register Listener

↓

Wait

↓

Event Happens

↓

emit("message")

↓

Listener Executes
```

---

# Syntax

```js
emitter.on(eventName, listener);
```

There are two main arguments:

```text
eventName

+

listener
```

---

# Basic Example

```js
const EventEmitter = require("events");

const emitter = new EventEmitter();

emitter.on("login", () => {

    console.log("User logged in");

});

emitter.emit("login");
```

Output:

```text
User logged in
```

---

# What `.on()` Actually Does

Consider:

```js
emitter.on("login", loginHandler);
```

It does **not** mean:

```text
Run loginHandler now
```

Instead:

```text
Store/Register loginHandler

↓

Associate it with "login"

↓

Wait for "login"
```

Later:

```js
emitter.emit("login");
```

Then:

```text
"login"

↓

Find Registered Listeners

↓

loginHandler()

↓

Execute
```

---

# Listener Registration

A listener is simply a function that waits for an event.

Example:

```js
function handleLogin() {

    console.log("Login detected");

}

emitter.on("login", handleLogin);
```

Here:

```text
handleLogin

↓

Listener for "login"
```

When:

```js
emitter.emit("login");
```

runs:

```text
handleLogin()
```

executes.

---

# Event Name

The first argument identifies the event.

```js
emitter.on("login", handleLogin);
```

Here:

```text
"login"

↓

Event Name
```

Event names are case-sensitive.

These are different:

```text
login

Login

LOGIN
```

Example:

```js
emitter.on("login", () => {

    console.log("Login");

});

emitter.emit("Login");
```

The listener will not execute.

Because:

```text
Registered:

"login"

Emitted:

"Login"
```

They are different events.

---

# Listener Function

The second argument is the function that should execute.

```js
emitter.on("login", () => {

    console.log("User logged in");

});
```

The function can also be defined separately.

```js
function handleLogin() {

    console.log("User logged in");

}

emitter.on("login", handleLogin);
```

Both approaches are valid.

---

# Do Not Call the Function

This is an important mistake.

Incorrect:

```js
emitter.on("login", handleLogin());
```

Why is this wrong?

Because:

```js
handleLogin()
```

calls the function immediately.

`.on()` expects a function to register.

Correct:

```js
emitter.on("login", handleLogin);
```

Now the function is registered.

---

# Multiple Listeners

One event can have multiple listeners.

Example:

```js
emitter.on("login", () => {

    console.log("Create Session");

});

emitter.on("login", () => {

    console.log("Send Notification");

});

emitter.on("login", () => {

    console.log("Update Analytics");

});
```

Now:

```js
emitter.emit("login");
```

produces:

```text
Create Session

Send Notification

Update Analytics
```

---

# Listener Execution Order

Listeners are normally called in the order in which they were registered.

Example:

```js
emitter.on("test", () => {

    console.log("First");

});

emitter.on("test", () => {

    console.log("Second");

});

emitter.on("test", () => {

    console.log("Third");

});
```

Then:

```js
emitter.emit("test");
```

Output:

```text
First
Second
Third
```

So:

```text
Registration Order

↓

Execution Order
```

---

# Passing Data

When the event is emitted, data can be passed to listeners.

Example:

```js
emitter.on("login", (username) => {

    console.log(`${username} logged in`);

});

emitter.emit("login", "Rahul");
```

Output:

```text
Rahul logged in
```

Flow:

```text
emit()

↓

"login"

+

"Rahul"

↓

Listener

↓

username = "Rahul"
```

---

# Passing Multiple Arguments

You can pass multiple arguments.

```js
emitter.on(
    "orderCreated",
    (orderId, amount, username) => {

        console.log(orderId);

        console.log(amount);

        console.log(username);

    }
);

emitter.emit(
    "orderCreated",
    101,
    5000,
    "Rahul"
);
```

The listener receives:

```text
orderId  → 101

amount   → 5000

username → Rahul
```

---

# Same Listener Multiple Times

The same function can be registered more than once.

Example:

```js
function handler() {

    console.log("Handler executed");

}

emitter.on("test", handler);

emitter.on("test", handler);
```

Now:

```js
emitter.emit("test");
```

The function can execute twice:

```text
Handler executed

Handler executed
```

Why?

Because two listener registrations were created.

Conceptually:

```text
"test"

↓

handler

↓

handler
```

This becomes important when we later study:

```text
removeListener()

off()

```

---

# `.on()` Is Reusable

Unlike `.once()`,

`.on()` keeps the listener registered.

Example:

```js
emitter.on("login", () => {

    console.log("Login");

});
```

Now:

```js
emitter.emit("login");

emitter.emit("login");

emitter.emit("login");
```

Output:

```text
Login
Login
Login
```

The listener remains registered.

---

# `.on()` vs `.once()`

We will study `.once()` properly in a later chapter.

For now, remember:

```text
.on()

↓

Every time event happens
```

```text
.once()

↓

Only first time
```

Example:

```js
emitter.on("test", handler);
```

Can execute:

```text
1st emit → handler

2nd emit → handler

3rd emit → handler
```

Whereas:

```js
emitter.once("test", handler);
```

executes only once.

---

# Return Value

`.on()` returns the same EventEmitter instance.

Example:

```js
const result = emitter.on("login", handler);

console.log(result === emitter);
```

Output:

```text
true
```

This allows method chaining.

Example:

```js
emitter
    .on("login", handleLogin)
    .on("logout", handleLogout)
    .on("error", handleError);
```

---

# Synchronous Execution

Remember:

`.on()` itself only registers the listener.

When `emit()` is called, listeners normally execute synchronously.

Example:

```js
const EventEmitter = require("events");

const emitter = new EventEmitter();

emitter.on("test", () => {

    console.log("Listener");

});

console.log("Before");

emitter.emit("test");

console.log("After");
```

Output:

```text
Before

Listener

After
```

Flow:

```text
Before

↓

emit()

↓

Listener Executes

↓

After
```

---

# Removing a Listener Later

Because `.on()` registers a listener, that listener can later be removed.

Example:

```js
function handleLogin() {

    console.log("Login");

}

emitter.on("login", handleLogin);
```

Later:

```js
emitter.off("login", handleLogin);
```

Now the listener is removed.

We will study this properly in:

```text
06-off-removeListener.md
```

Important:

If you want to remove a specific listener, you normally need the **same function reference** that was registered.

This works:

```js
function handler() {}

emitter.on("test", handler);

emitter.off("test", handler);
```

This does not remove the original listener:

```js
emitter.on("test", () => {});

emitter.off("test", () => {});
```

Why?

Because these are two different function objects.

# Production Example

Imagine an application where a user places an order.

We can register different listeners for:

```text
order.created
```

Example:

```js
const EventEmitter = require("events");

const eventBus = new EventEmitter();

eventBus.on("order.created", (order) => {

    console.log(
        `Update inventory for ${order.id}`
    );

});

eventBus.on("order.created", (order) => {

    console.log(
        `Send email for ${order.id}`
    );

});

eventBus.on("order.created", (order) => {

    console.log(
        `Create notification for ${order.id}`
    );

});
```

Later:

```js
eventBus.emit(
    "order.created",
    {
        id: 101,
        amount: 5000
    }
);
```

Flow:

```text
order.created

├── Inventory Listener
│
├── Email Listener
│
└── Notification Listener
```

This is the basic foundation of event-driven application design.

---

# Important Production Point

Do not assume that multiple listeners automatically run in parallel.

They are normally invoked synchronously in registration order.

So this:

```text
Listener A

↓

Listener B

↓

Listener C
```

is not automatically:

```text
A ──────────┐
B ──────────┼── Parallel
C ──────────┘
```

If a listener performs expensive synchronous work, it can delay the listeners that come after it.

# Common Mistakes

## Mistake 1 — Calling the Listener

Wrong:

```js
emitter.on("login", login());
```

Correct:

```js
emitter.on("login", login);
```

---

## Mistake 2 — Wrong Event Name

```js
emitter.on("userCreated", handler);

emitter.emit("usercreated");
```

No match.

Event names are case-sensitive.

---

## Mistake 3 — Assuming `.on()` Runs the Function

This:

```js
emitter.on("login", handler);
```

only registers.

The function executes when:

```js
emitter.emit("login");
```

happens.

---

## Mistake 4 — Forgetting Duplicate Registrations

If the same function is registered twice:

```js
emitter.on("test", handler);

emitter.on("test", handler);
```

it can execute twice.

---

## Mistake 5 — Trying to Remove an Anonymous Function

This is difficult to remove later:

```js
emitter.on("login", () => {

    console.log("Login");

});
```

If you need to remove it later, keep a reference:

```js
const handler = () => {

    console.log("Login");

};

emitter.on("login", handler);

emitter.off("login", handler);
```

# Summary

The basic syntax is:

```js
emitter.on(eventName, listener);
```

It means:

```text
Register this function

↓

for this event

↓

and execute it whenever that event is emitted.
```

Important points:

```text
.on()

↓

Registers Listener

↓

Doesn't execute immediately

↓

Listener remains registered

↓

Can execute on every emit
```

---

# Key Takeaways

- `.on()` registers an event listener.
- It does not execute the listener immediately.
- The listener executes when the corresponding event is emitted.
- One event can have multiple listeners.
- Listeners normally execute in registration order.
- `.on()` listeners remain registered until removed.
- Event data can be received through listener parameters.
- The same listener can be registered multiple times.
- `.on()` returns the EventEmitter instance.
- Keep a function reference if you may need to remove the listener later.
- Multiple listeners are not automatically parallel.
